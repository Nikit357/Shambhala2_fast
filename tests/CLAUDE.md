# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Test Suite Overview

~109 pytest tests: 5 unit-test files, 1 integration file, `test_s0_reuse.py` (benchmark Case A/B/C routing, mocked S3), and `speed_up_tests/` (one file per approach + `test_combinations.py`). Tests that require Octave are auto-skipped when Octave is unavailable; all pure-Python tests run unconditionally.

## Commands

```bash
# All tests from the repo root
cd /home/jovyan/Projects/Shambhala2_fast
pytest tests/ -v --timeout=3600

# Unit tests only — no Octave required, < 30 s
pytest tests/ -v --ignore=tests/speed_up_tests/ --timeout=60

# Speed-up tests — all, including timing tests (default)
pytest tests/speed_up_tests/ -v --timeout=3600

# Speed-up tests — skip timing tests for faster CI
pytest tests/speed_up_tests/ -v -m "not slow" --timeout=3600

# Speed-up tests — quick sanity check, 20-minute cap
pytest tests/speed_up_tests/ -v -m "not slow" --timeout=1200

# Single test file
pytest tests/test_octave_bridge.py -v

# Single test
pytest tests/test_q_rescale.py::test_rescale_known_values -v

# Only Octave-requiring tests (verbose failure on missing Octave)
pytest tests/ -v -k "not (test_bridge_raises or test_bridge_error or test_bridge_raises_on_unparseable or test_tsv or test_is_progress or test_parse_progress or test_random_seed)"

# Regenerate all fixtures (requires Shambhala2/ as sibling of Shambhala_containerized/)
# Must be run from Shambhala_containerized/ because it imports the shambhala package
python tests/generate_fixtures.py
```

**Timeouts.** `pytest-timeout` must be installed (`pip install pytest-timeout`). Every speed-up test that calls Octave or Python CuBlock is decorated with `@pytest.mark.timeout(3600)` (1 hour). The global default `timeout = 3600` in `pyproject.toml` is a fallback for any test that lacks the decorator. Override per run with `--timeout N`.

## Octave Skip Pattern

All files that call Octave use the same guard:

```python
_OCTAVE_AVAILABLE = pathlib.Path("/opt/conda/bin/octave").exists() or shutil.which("octave") is not None
octave_required = pytest.mark.skipif(not _OCTAVE_AVAILABLE, reason="Octave not installed ...")
```

Tests decorated with `@octave_required` skip silently when Octave is absent.

## Key Test Patterns

### `_run_pipeline()` helper (test_integration.py)
Manually replicates the `main()` logic from `run_shambhala.py` inside the test. Avoids subprocess overhead of calling the CLI. Used by all integration tests.

### Mocking subprocess.run (test_octave_bridge.py)
Several unit tests patch `subprocess.run` to inject fake return codes or stdout without invoking Octave:
```python
with patch("subprocess.run", return_value=fake_result):
    run_octave_normalize(...)
```

### Tolerance for numerical tests

**Unit tests and integration baselines:**
- Integration determinism (`test_single_worker_matches_reference`): `atol=1e-4, rtol=0`
- Parallel vs single-worker consistency (`test_parallel_matches_single`): per-gene mean `rtol=0.05` (k-means randomness causes per-sample variation, but gene means converge)
- Q-rescale arithmetic (`test_rescale_known_values`): `atol=1e-10`

**Speed-up tests — primary metric is `mean_rel_diff`:**

`mean_rel_diff` = mean of `|result − expected| / |expected|` across all genes and samples, with zero-protection on the denominator. Applied via the shared `assert_mean_rel_diff` helper in `speed_up_tests/conftest.py`.

| Tier | `mean_rel_diff` | Test outcome | Interpretation |
|---|---|---|---|
| PASSED | < 1% | Green | Production-safe |
| WARNING | 1%–5% | Green + warning | Exploratory only; not for benchmarking |
| FAILED | > 5% | Red | Unacceptable systematic distortion |

Approach A+synthetic uses wider tiers (warn > 10%, fail > 20%).

`max_abs_diff` is printed by every speed-up test for diagnostic purposes but is not the assertion basis. In raw expression scale (post Q-rescaling), values can reach ~100 000; absolute thresholds are dominated by a handful of outlier genes and are not informative for overall quality assessment.

### Progress renderer tests use `use_ansi=False`
`_make_renderer(..., use_ansi=False)` forces plain-text mode so tests can assert on plain string output without ANSI escape sequences.
